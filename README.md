# OpenBao в закрытом контуре

В каталоге уже есть всё, чтобы поднять OpenBao 2.6.2 на одной машине x86_64. Интернет на целевой машине не нужен. Пакеты лежат в `files/`: deb для Debian и Ubuntu, rpm для RHEL и совместимых систем.

На машине нужны `openssl` и systemd. Они есть в любой штатной установке, а если `openssl` нет, поставьте его с установочного носителя ОС. Проверено на Debian 12 и 13, Ubuntu 22.04 и 24.04, Rocky Linux 8 и 9.

## Развернуть

Скопируйте этот каталог на сервер и выполните:

```bash
sudo ./install.sh
```

Если при копировании пропал бит исполнения (WinSCP, флешка), запускайте `sudo bash install.sh`.

Скрипт сверяет sha256, ставит пакет, выпускает сертификат на IP машины, открывает порт 8200 в firewalld или ufw, если они включены, запускает сервис, инициализирует хранилище и снимает печать. Повторный запуск безопасен: скрипт меняет только то, что отличается, и в конце пишет, что именно изменил.

С другой машины внутри контура:

```bash
./deploy.sh root@10.0.0.5
./deploy.sh admin@10.0.0.5     # не root: install.sh запустится через sudo
```

`deploy.sh` отправляет установщик и один нужный пакет в `~/openbao-install` на сервере и запускает его там. На сервере нужны `bash` и `cat`, `tar` не нужен. Не под root нужен `sudo`; если он спрашивает пароль, запускайте `deploy.sh` из терминала.

## Настройки

Переменные окружения для `install.sh`. `deploy.sh` передаёт их дальше.

| Переменная | Что делает |
|---|---|
| `OPENBAO_API_ADDR=https://10.0.0.5:8200` | Адрес для клиентов, если у машины несколько IP или нужно DNS-имя. Сертификат выпускается на этот адрес |
| `OPENBAO_CLUSTER_ADDR=https://10.0.0.5:8201` | Адрес кластера, по умолчанию тот же хост и порт 8201 |
| `OPENBAO_FIREWALL=0` | Не трогать firewalld и ufw |
| `OPENBAO_AUTO_UNSEAL=1` | Снимать печать автоматически после каждого старта сервиса. `0` выключает |

```bash
sudo OPENBAO_API_ADDR=https://10.0.0.5:8200 ./install.sh
```

Конфиг `/etc/openbao/openbao.hcl` пишется при первой установке и когда `OPENBAO_API_ADDR` или `OPENBAO_CLUSTER_ADDR` задаёт адрес, отличный от того, что в конфиге. Тогда сервис перезапускается и печать снимается заново. В остальных случаях повторный запуск оставляет конфиг как есть, вместе с ручными правками, и берёт адрес из него. `node_id` не меняется никогда: raft с другим `node_id` не поднимется.

## Что получится

Сервис слушает `https://<ip>:8200` на всех интерфейсах. Интерфейс: `https://<ip>:8200/ui`.

Ключ unseal и root token записаны в `/root/openbao-init.txt`, права `0600`. Для входа в интерфейс нужен root token из этого файла.

Сертификат самоподписанный, выпущен на 825 дней на адрес сервера, `127.0.0.1` и `localhost`. Клиентам нужен файл `/etc/openbao/tls/tls.crt` как доверенный:

```bash
export BAO_ADDR='https://<ip>:8200'
export BAO_CACERT=/etc/openbao/tls/tls.crt
bao status
```

На самом сервере эти переменные уже заданы в `/etc/profile.d/openbao.sh` для всех пользователей.

Если до конца срока сертификата осталось меньше 30 дней, повторный `sudo ./install.sh` перевыпустит его без перезапуска: сервер останется распечатан. Если у сервера сменился адрес, запустите `sudo OPENBAO_API_ADDR=https://<новый адрес>:8200 ./install.sh`: конфиг и сертификат перепишутся, сервис перезапустится, и печать снимется, если ключ на сервере. В обоих случаях раздайте клиентам новый `tls.crt`.

## Перезагрузка и печать

Печать одна, порог один: это установка на одну машину, ключ лежит на ней же. После перезагрузки или падения сервиса сервер снова sealed. Снять печать:

```bash
sudo openbao-unseal
```

Команда берёт ключ из `/root/openbao-init.txt`. Если файла на сервере нет, она спросит ключ, не показывая его на экране, и будет спрашивать, пока не наберётся порог. Ключи передаются OpenBao через stdin и не попадают в список процессов. Повторный `sudo ./install.sh` тоже снимет печать.

Если ключ должен храниться отдельно, заберите `/root/openbao-init.txt` с сервера. Если отдельно хранить не нужно, `OPENBAO_AUTO_UNSEAL=1` снимает печать сама после перезагрузки и падения, пока файл на месте.

## Свой сертификат

Положите `files/tls.crt` и `files/tls.key` до запуска, нужны оба, в PEM, ключ без пароля. Скрипт проверит, что ключ подходит к сертификату и что сертификат выпущен на адрес сервера, и остановится, ничего не меняя, если это не так. Сертификат на DNS-имя требует `OPENBAO_API_ADDR=https://<это имя>:8200`. Новый сертификат на работающем сервере подхватывается без перезапуска.

В git эти файлы не попадают. После установки уберите оба файла из каталога: сертификат уже лежит в `/etc/openbao/tls`, и повторные запуски его не тронут. `deploy.sh` удаляет их с сервера сам.

## Ansible

Если Ansible уже есть на управляющей машине, тот же каталог ставится playbook'ом. Роль копирует `install.sh` и пакет в `/root/openbao-install` на каждом хосте и запускает его там, поэтому результат тот же, что у ручной установки, вместе с инициализацией и снятием печати.

```bash
cp inventory/hosts.ini.example inventory/hosts.ini   # впишите адреса и ansible_user
ansible-playbook -i inventory/hosts.ini openbao.yml -K
```

Нужен ansible-core 2.15 или новее. На целевых машинах нужен `python3` той версии, которую поддерживает ваш ansible-core (для 2.21 это 3.9 и новее): поставьте его с носителя ОС. Если заходите под root на машину без `sudo`, добавьте хосту `ansible_become=false`. Адрес API берётся из `ansible_host`, остальные переменные описаны в `roles/openbao/defaults/main.yml`. Если ключа на хосте нет, а сервер запечатан, прогон остановится с ошибкой: снимите печать через `sudo openbao-unseal` на хосте.

## Обслуживание

Журнал сервиса: `journalctl -u openbao -f`. Строка `failed to unlock initialization lock: cannot find peer` при первой инициализации штатная.

Журнал аудита: `/var/log/openbao/audit.log`, ротация раз в сутки, хранятся 30 файлов. Если OpenBao не может писать в этот журнал, он отказывает в запросах, поэтому следите за местом на `/var`. Блок аудита есть в конфиге, который пишет `install.sh`. В свой или старый конфиг добавьте его вручную и перезапустите сервис:

```hcl
audit "file" "file" {
  options {
    file_path = "/var/log/openbao/audit.log"
  }
}
```

Резервная копия:

```bash
sudo -i
export BAO_TOKEN=<root token>
bao operator raft snapshot save /root/openbao-$(date +%F).snap
```

Снимок восстанавливается командой `bao operator raft snapshot restore` и открывается только ключом unseal того времени, когда он сделан. Храните снимки вместе с этим ключом, но отдельно от сервера. При повторной инициализации прежний `openbao-init.txt` не пропадает: он сохраняется рядом с датой в имени.

Обновление: сделайте снимок, положите новый пакет в `files/`, добавьте его строку в `checksums.txt` и поменяйте `VERSION` в `install.sh`. `deploy.sh` и роль берут версию оттуда же. Запустите установку как обычно: сервис перезапустится, и скрипт снимет печать, если ключ на сервере. Откатить установленную более новую версию скрипт откажется. Пакет, закреплённый через `apt-mark hold`, он не трогает.

Root token лучше не использовать в работе: заведите администраторам свой метод входа и политику, затем отзовите токен (`bao token revoke`). Новый root token выпускается командой `bao operator generate-root` с ключом unseal.

Удаление, данные и ключи пропадут:

```bash
sudo systemctl disable --now openbao
sudo apt purge openbao       # или: sudo dnf remove openbao
sudo rm -rf /opt/openbao /etc/openbao /var/log/openbao /root/openbao-init.txt* \
  /etc/profile.d/openbao.sh /etc/logrotate.d/openbao /usr/local/sbin/openbao-unseal \
  /etc/systemd/system/openbao.service.d
```

## Проверка изменений

`tests/run.sh` прогоняет установку, повторные запуски и сбои в контейнерах с systemd для каждой поддерживаемой системы. Нужен Docker с доступом к Docker Hub. На Apple Silicon образы amd64 идут через эмуляцию: медленно, а Debian 13 под ней не запускает сервисы systemd. Положите в `files/` arm64-пакеты той же версии из релиза OpenBao, и тесты пойдут без эмуляции. В git эти пакеты не попадают.
