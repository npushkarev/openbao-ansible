# OpenBao в закрытом контуре

В каталоге уже есть всё, чтобы поднять OpenBao 2.6.2 на одной машине x86_64. Интернет на целевой машине не нужен. Пакеты лежат в `files/`: deb для Debian и Ubuntu, rpm для RHEL и совместимых систем.

На машине заранее должен стоять `openssl` с установочного носителя ОС. Других зависимостей нет.

## Развернуть

Скопируйте этот каталог на сервер и выполните:

```bash
sudo ./install.sh
```

Скрипт сверяет sha256, ставит пакет, выпускает сертификат на IP машины, запускает сервис, инициализирует хранилище и сразу снимает печать.

Если копируете с другой машины уже внутри контура:

```bash
./deploy.sh root@10.0.0.5
```

Свой адрес, если у машины несколько IP:

```bash
sudo OPENBAO_API_ADDR=https://10.0.0.5:8200 ./install.sh
```

## Что получится

Сервис слушает `https://<ip>:8200`. Интерфейс: `https://<ip>:8200/ui`.

Ключ unseal и root token записаны в `/root/openbao-init.txt`, права `0600`. Для входа в интерфейс нужен root token из этого файла. Клиент доверяет сертификату так:

```bash
export BAO_ADDR='https://<ip>:8200'
export BAO_CACERT=/etc/openbao/tls/tls.crt
bao status
```

Те же переменные попадают в `/etc/profile.d/openbao.sh` для новых сессий.

Печать одна, порог один: это установка на одну машину, ключ лежит на ней же. Если ключ должен храниться отдельно, заберите `/root/openbao-init.txt` с сервера. После перезагрузки сервер снова sealed. Повторный `sudo ./install.sh` снимет печать тем же ключом, либо вручную:

```bash
bao operator unseal "$(awk -F': ' '/^Unseal Key 1:/ {print $2; exit}' /root/openbao-init.txt)"
```

Свой сертификат вместо выпущенного скриптом: положите `files/tls.crt` и `files/tls.key` до запуска.

## Ansible

Тот же каталог ставится playbook'ом, если Ansible уже есть на управляющей машине. Playbook только ставит и запускает сервис, инициализацию не делает.

```bash
cp inventory/hosts.ini.example inventory/hosts.ini
ansible-playbook openbao.yml
```

Адрес API берётся из `ansible_host`. Дальше инициализация той же командой `bao operator init` либо повторным `sudo ./install.sh` на сервере.
